### Step 2: Saving State (History and Cache)

**What is evaluated:**

**How values are passed:** `validated_response` and `q_emb` are passed down to internal persistence structures.

**What is executed:** The `parse_rag_response()` validation function from `rag_models.py`.
**What is evaluated:** It converts the `raw_llm_output` (a Pydantic model) back into a dictionary, then re-validates it to strictly enforce the confidence threshold (raising a `ValueError` if confidence < 0.5).
**How values are passed:** The raw output generated by the LLM is passed into the validator. The sanitized `RAGResponse` is assigned to `validated_response`.

### Step 4: Generating the Structured Output
```python

```
**What is executed:** The LLM's invocation method with strict schema enforcement.
**What is evaluated:** The language model receives the prompt messages. Instead of returning raw unstructured text, it uses OpenAI's structured output API (or similar tool calling) to guarantee the output perfectly matches the schema of the `RAGResponse` Pydantic model.
**How values are passed:** The array of `prompt_msgs` is passed to the LLM. It returns an instantiated `RAGResponse` object (`raw_llm_output`).

### Step 5: Constructing the Prompt Messages

**What is executed:** String formatting and list concatenation.
**What is evaluated:** A strict instructional prompt is created injecting the retrieved context strings. This `SystemMessage` is prepended to the array of previous chat history `messages` (acting as a sliding window).
**How values are passed:** `context_str` (the retrieved chunks) and `messages` (the chat history up to 6 turns) are combined into the final `prompt_msgs` list.

### Step 6: Context Retrieval and Token Budgeting
```python
docs = self._retriever.invoke(query)
raw_chunks = [d.page_content for d in docs]
chunks = truncate_to_token_budget(raw_chunks, max_tokens=1500)
context_str = "\n\n".join(chunks)
```
**What is executed:** FAISS vector retrieval, list comprehension, and the `truncate_to_token_budget` utility.
**What is evaluated:** 
- The FAISS index finds the top-k most similar document chunks for the `query`.
- `tiktoken` counts the exact token length of each chunk. It discards chunks that would push the total context past the 1500 token limit.
- The remaining chunks are joined by double newlines to form `context_str`.
**How values are passed:** The `query` string hits the vector database; the returned texts (`raw_chunks`) hit the token truncator, which outputs the safe `chunks`.

### Step 7: Semantic Caching Interception

**What is executed:** Embedding generation and cache lookup via Cosine Similarity.
**What is evaluated:** The query is converted into a high-dimensional vector. If the `SimpleCache` finds a previously answered query with a similarity score >= 0.90, it instantly returns the cached response, completely short-circuiting Steps 3-6.
**How values are passed:** The `query` is passed to the embedding model.

### Step 8: Input Guardrails
```python

```
**What is executed:** The `check_input_guardrail()` function.
**What is evaluated:** Before any heavy lifting, the raw input is scanned using regular expressions to detect prompt injection (e.g., "ignore previous instructions") or queries that are too short. If detected, it immediately throws a `ValueError`.
**How values are passed:** The raw `query` string from the user is evaluated. If it passes, the pipeline continues down to Step 7.
